## Independent service and client interfaces (D12)

Checked through the live LangChain documentation MCP on 26 October 2026 for the owner's P24 decision. Reuse these interfaces where they qualify before proposing a custom client protocol:

- [Agent Server streaming](https://docs.langchain.com/langsmith/streaming): JavaScript/Python SDK and HTTP examples create threads and stream runs. This supports a service interface usable beyond a browser; it does not deliver our CLI or qualify a mobile SDK/runtime.
- [Client authentication](https://docs.langchain.com/langsmith/custom-auth#javascript-client): JavaScript client requests can carry authentication headers. Qualify the actual TypeScript server-side authentication/authorisation mechanism and local distribution requirements; documentation examples are not a selected auth provider or an application-account requirement.
- [Frontend join/rejoin](https://docs.langchain.com/oss/javascript/langchain/frontend/join-rejoin): documented same-thread reconnect, server-side continuation and disconnect-versus-cancel patterns require a compatible Agent Server. Checkpoints alone do not keep a host process alive. Mobile background/reconnect examples establish a framework pattern, not verified native-mobile integration, offline execution or a sync engine for this application.

Application responsibilities remain service-owned admission/permissions, provider credential access, local process lifetime and appropriate client presentation, using maintained integrations wherever qualified. M1-01 assesses these boundaries; a gap still requires owner agreement before bespoke implementation. M1 ships only the desktop client. CLI/mobile design and networking/auth decisions are triggered later by DT-11; no extra client, listener, cloud deployment or remote exposure is implemented by this plan update.

Use current live TypeScript docs to resolve stale or Python-only skill examples. These skills do not supply a ready-made mobile application or establish that an existing Deep Agents terminal application can attach to our product service.

## Framework versus application implementation briefing

Owner preference: prefer supported abstractions/configuration over bespoke code, with agreement before a custom component is implemented. The following is a qualitative planning assessment, not a measured percentage of implementation effort. Nothing here claims the scaffold has these capabilities configured.

| Area                                | Reuse/configuration first                                                                                  | Remaining work or qualification                                                                                                                                                                                                  |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Agent execution                     | createDeepAgent, supported model integrations, harness profiles and middleware                             | Agent definitions/configuration; qualify exact exposed tools and disable M1 delegation through supported profile controls. Do not build another loop.                                                                            |
| Streaming and approvals             | Framework stream/event APIs, frontend SDK and interrupt/resume semantics                                   | Figma presentation and binding to a compatible service; do not invent a parallel event protocol without a demonstrated gap.                                                                                                      |

Most agent mechanics should come from framework configuration and integration. Much of the remaining delivery effort is the desktop product and local execution/distribution integration; Deep Agents is a harness, not a ready-made offline desktop product. No reliable code/effort percentage exists before M1-01 qualification.

The current live [production guidance](https://docs.langchain.com/oss/javascript/deepagents/going-to-production#langsmith-deployments) recommends Managed Deep Agents on LangSmith Cloud and also documents other deployments. Managed deployments provision threads/runs/store/checkpoints and other service capabilities; those are not included merely by installing the OSS package. Local-first is an agreed product requirement, so evaluate maintained locally deployable options before building equivalents. Any unavoidable custom gap must be brought to the owner with alternatives and trade-offs.

M1-01 must deliver a reuse decision per component: exact library/version/source, configuration-only path, integration glue, capability gap, supported alternatives, proposed custom boundary (if any), acceptance evidence and owner agreement status. Do not implement a custom component while its agreement is pending. This requirement is now part of every milestone issue.
